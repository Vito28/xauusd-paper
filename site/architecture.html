Arsitektur Sistem¶

Boundary¶

Lapisan collector hanya melakukan extract, validation, metadata/timestamp normalization, store, dan audit. Collector tidak melakukan trading, indikator, feature engineering, normalisasi ML, penghapusan outlier, interpolation, atau training. Analytics membaca data melalui transaksi read-only dan melakukan analisis pada salinan tanpa mengubah data sumber.

MetaTrader 5
  -> market.profile (broker TOML + validated GOLD_* settings)
  -> market.collector / MT5 provider (external boundary, read-only)
  -> market.collector / validation (pure normalization + invariant checks)
  -> market.collector / ingestion (partition/retry/transaction orchestration)
  -> database.storage (session/transaction + bulk persistence)
  -> PostgreSQL schemas core/ingest/market/audit
  -> market.dashboard (local read-only table and JSON API)
  -> analytics.data / analytics.analytics (query read-only, EDA dan time series)

Untuk deployment lokal berbasis container, Docker Compose menyediakan dua service: postgres menjalankan PostgreSQL 18 dan api menjalankan FastAPI dengan Python 3.12 serta environment yang dikelola uv. Service API menunggu health check PostgreSQL, menjalankan migrasi Alembic, lalu membuka dashboard. MetaTrader 5 tetap berada di boundary Windows host karena library resminya tidak tersedia untuk container Linux.

MT5 hanya diakses oleh command source-register, mt5-info, symbol-info, ingest-bars, ingest-ticks, sync-bars, dan sync-ticks. Import module, pytest discovery, serta Alembic tidak menginisialisasi terminal.

Workflow market¶

Dua file utama acquisition adalah market/profile.py dan market/collector.py, keduanya memakai section # %% dan komentar proses seperti notebook. profile.py berisi schema/loader/saver broker TOML dan runtime settings. save_broker_profile() memvalidasi serta menyimpan konfigurasi non-secret ke configs/brokers/, dengan penggantian file melalui overwrite=True eksplisit.

collector.py menyatukan symbol resolution, MT5 provider/preflight, UTC partition, bar/tick validation, derived aggregation/gap, ingestion/retry/checkpoint, coverage/status/validation reports, logging dan Typer CLI. contracts.py tetap menjadi kontrak record bersama repository; dashboard.py tetap menjadi API/browser read-only. cli.py hanya menghubungkan launcher lama ke app collector. Repository menunda import fingerprint collector sampai save_symbol_spec() dipanggil untuk menghindari circular import.

Import tidak mengaktifkan settings, MT5, atau koneksi database. Profile TOML, policy retry, transaksi atomik dan format data tidak berubah oleh penggabungan. Lihat market/README.md dalam source repository untuk peta section dan contoh config.

Persistence database¶

Dua file utama persistence adalah database/schema.py dan database/storage.py, dengan section # %% dan komentar proses. schema.py memuat seluruh ORM mappings: source, symbol spec, ingestion run, checkpoint, bars, ticks dan rejection. storage.py memuat lazy engine/session lifecycle, transaksi dan empat repository source/market data/ingestion/rejection. Collector, dashboard dan analytics menggunakan API storage yang sama; schema metadata tersedia untuk Alembic.

database/migrations/ tetap menyimpan runtime/template serta riwayat revisi Alembic. Struktur tabel, constraints dan migration revision IDs dipertahankan; refactor ini tidak menjalankan perubahan pada database aktif. Lihat database/README.md dalam source repository untuk peta section dan import baru.

Data model dan provenance¶

core.data_source mengikat satu source_key ke broker, server, environment, canonical dataset symbol, dan actual symbol. Source berbeda tidak dicampur. core.symbol_spec_version menyimpan snapshot metadata berdasarkan payload hash, karena specification sekarang tidak boleh diasumsikan berlaku untuk 10 tahun.

ingest.run adalah audit satu invocation. ingest.checkpoint adalah resume state per fixed partition. market.bar_observation dan market.tick_observation append-only serta dipartisi bulanan. market.rejection mempertahankan payload invalid untuk diagnosis.

Views¶

  • market.bar_latest: revision terbaru per logical candle; raw revision lama tetap ada.
  • market.data_coverage: requested partitions versus actual record coverage.
  • market.quote_ohlc_m5: Bid/Ask OHLC dan statistik spread dari tick valid saja.
  • market.processed_m5: view siap-riset yang menggabungkan native M5 terbaru, provenance source, dan quote M5 dengan LEFT JOIN. Native candle tetap tampil ketika historical tick tidak tersedia; pada kondisi itu kolom quote bernilai NULL.

Native bar dan quote OHLC adalah dataset berbeda. Higher timeframe dari M5 juga merupakan derived dataset; native M5 tetap dipertahankan.

market.dashboard membaca market.bar_latest, market.tick_observation, dan market.processed_m5 melalui query terparameterisasi. Dataset serta kolom sorting dipilih dari whitelist server. Dashboard tidak menginisialisasi MT5 dan tidak menyediakan operasi tulis database. Satu instance dashboard dapat membaca database demo atau live melalui pilihan environment yang dibatasi ke demo/live; URL koneksi masing-masing tetap berada di server pada GOLD_DASHBOARD_DEMO_DATABASE_URL dan GOLD_DASHBOARD_LIVE_DATABASE_URL, bukan di browser.

Security dan isolation¶

Demo/live wajib memakai database berbeda. Runtime memvalidasi environment pada settings, profile, dan account MT5 aktual. Logs tidak memuat password, DSN, login, account number, token, atau secret. Credential MT5 tidak disimpan dalam database aplikasi maupun repository.

Analytics dalam dua file¶

analytics/data.py menangani query PostgreSQL read-only dan transformasi data pada salinan: UTC/provenance, candle tertutup, return native dengan gap mask, serta agregat sesi UTC harian tanpa imputation. analytics/analytics.py menangani section UNI/BI/MULTI, grafik time series, model Ridge return dengan expanding folds dan holdout 2026, evaluasi split model beku, forecast XGBoost yang dipertahankan, serta satu CLI. Scaler fit training per fold; target yang melewati boundary dipurge. Plot dan metrik ditulis sebagai artifact turunan, sedangkan database tetap source of truth. Panduan dan paper tersedia di analytics README.
